# Prompt Engineering: System Messages & Prompt Patterns

# 1. Message Types

A conversation with an AI model consists of three primary message types.

## System Message

The **System Message** defines the assistant's behavior, role, and constraints. It is processed first and has the highest priority.

**Purpose**

- Defines the assistant's role
- Sets behavior and boundaries
- Controls tone and communication style
- Specifies output format
- Applies safety and quality constraints

Example

```text
You are a helpful technical support assistant.
Provide concise and accurate troubleshooting steps.
```

---

## User Message

The **User Message** contains the user's question, request, or instruction.

Example

```text
How do I deploy a FastAPI application to Azure?
```

---

## Assistant Message

The **Assistant Message** contains previous responses generated by the AI.

These messages help maintain context during multi-turn conversations.

Example

```text
To deploy a FastAPI application, first create an Azure App Service...
```

---

# Conversation Flow

```text
System Message
      │
      ▼
```

# 2. System Messages

A **System Message** is a set of instructions provided to the model before the conversation begins.

It guides how the assistant behaves throughout the interaction.

System messages can be used to:

- Define the assistant's role
- Set communication style
- Specify response format
- Enforce business rules
- Apply safety constraints
- Control response quality

---

# 3. Designing Effective System Messages

A well-designed system message should clearly define what the assistant should do and how it should respond.

## Purpose

A system message helps to:

- Define the assistant's responsibilities
- Improve consistency
- Reduce ambiguity
- Produce predictable outputs
- Improve response quality

---

# 4. System Message Checklist

When writing a system message, follow these best practices.

## 1. Define the Assistant's Role

Clearly describe who the assistant is and what it should accomplish.

Example

```text
You are a software engineering assistant that explains programming concepts with practical examples.
```

---

## 2. Define Boundaries

Specify topics or actions the assistant should avoid.

Examples

- Don't generate harmful content.
- Don't provide medical or legal advice.
- Don't invent facts.
- Don't reveal confidential information.

---

## 3. Specify the Output Format

If responses must follow a specific format, describe it explicitly.

Examples

- Markdown
- JSON
- Bullet points
- Tables
- Numbered lists

Example

```text
Respond using:

- Summary
- Explanation
- Example
```

---

## 4. Add a "When Unsure" Policy

Tell the model how to respond when information is missing or ambiguous.

Examples

- Ask clarifying questions.
- State uncertainty instead of guessing.
- Explain any limitations.

Example

```text
If you are unsure, ask the user for more information before answering.
```

---

# Example System Message

```text
You are an Azure AI assistant.

Your responsibilities are:
- Answer Azure AI questions accurately.
- Explain concepts using simple language.
- Use Markdown formatting.
- Include code examples where appropriate.

Do not make up information.

If the request is unclear, ask a clarifying question before responding.
```

# 5. Prompt Engineering Patterns

Prompt engineering patterns improve response quality by guiding how the model should think and format its answers.

---

## Persona Pattern

Assign a role or personality to the assistant.

Example

```text
You are an experienced Python developer.
Explain concepts using beginner-friendly examples.
```

### Common Personas

- Software Engineer
- Technical Writer
- Teacher
- Interviewer
- Financial Advisor
- Cloud Architect

---

## Format Template Pattern

Specify a fixed response structure.

Example

```text
Summarize the topic using:

- Overview
- Advantages
- Disadvantages
- Conclusion
```

Benefits

- Consistent responses
- Easy to read
- Easy to parse programmatically

---

## Chain-of-Thought Pattern

Guide the model to work through complex problems step by step before producing an answer.

Example

```text
Solve the problem step by step before giving the final answer.
```

Best suited for

- Mathematics
- Programming
- Logic problems
- Multi-step reasoning

> **Note:** For production applications, it's generally preferable to ask for a concise explanation or solution rather than requesting the model's internal reasoning process.

---

## Few-Shot Learning Pattern

Provide examples of the expected input and output so the model learns the desired style or format.

Example

```text
Input: Hello
Output: Hi! How can I help you today?

Input: Bye
Output: Goodbye! Have a great day.
```

Benefits

- Improves consistency
- Reduces ambiguity
- Produces more predictable outputs
- Helps with custom formatting

---

# Fine-Tuning

Fine-tuning trains a pre-trained model on custom data to improve performance for a specific task when prompt engineering isn't enough.

### When to Fine-Tune

- **Consistent Style & Tone** – Maintain a specific brand voice.
- **Structured Output** – Generate consistent JSON, XML, SQL, etc.
- **Reduce Prompt Length** – Embed instructions into the model to save tokens.
- **Distillation** – Transfer knowledge from a large model to a smaller, cheaper model.
- **Tool Usage** – Improve tool selection and parameter generation.

---

## Fine-Tuning Techniques

### Supervised Fine-Tuning (SFT)
- Uses labeled prompt-response pairs.
- Best for well-defined tasks like chat, summarization, and classification.

### Reinforcement Fine-Tuning (RFT)
- Improves responses using rewards and feedback.
- Best for reasoning and complex tasks.

### Direct Preference Optimization (DPO)
- Learns from preferred vs. non-preferred responses.
- Simpler and more efficient than traditional reinforcement learning.

---

## LoRA (Low-Rank Adaptation)

- A **Parameter-Efficient Fine-Tuning (PEFT)** technique.
- Keeps the original model **frozen**.
- Trains only small **adapter layers** instead of the entire model.

### Benefits

- Lower training cost
- Faster training
- Less GPU memory
- Smaller model updates
- Easy to switch between tasks

---

## Challenges

- Training and hosting costs
- Requires high-quality training data
- May need retraining over time
- Hyperparameter tuning (epochs, batch size, learning rate)
- Risk of overfitting or model drift
